# Messaging Component

## Overview

The Messaging component is part of the Cupid dating application developed for COIT13235 Enterprise Software Development.

Its purpose is to allow users to send messages to other users, view previous messages, access conversation history, and view message threads.

The component follows a layered Spring Boot architecture using a controller, service, repository, JPA entity, Thymeleaf views, and an H2 database.

## Main Features

The Messaging component currently supports:

- Sending messages between users
- Viewing all stored messages
- Viewing the conversation history between two users
- Viewing message threads for a selected user
- Sanitising message input before persistence
- Displaying an optional encouragement message to users
- Enabling or disabling the encouragement feature using one configuration setting
- Persisting messages using Spring Data JPA
- Handling persistence failures through a custom MessagingException
- Applying a configurable persistence timeout
- Displaying a user-friendly error page when messaging operations fail

## Component Structure

The Messaging component is separated into multiple layers.

### Model

`Message`

Represents a persisted message.

A message contains:

- id
- sender
- receiver
- content
- sentAt

The class is mapped as a JPA entity.

### Repository

`MessageRepository`

Extends:

`JpaRepository<Message, Long>`

The repository provides persistence operations and Spring Data derived queries for:

- retrieving a conversation between two users
- retrieving messages involving a particular user
- ordering messages by time

### Service

`MessagingService`

Contains the main business logic for the component.

Responsibilities include:

- sanitising user input
- creating messages
- saving messages
- retrieving all messages
- retrieving conversation history
- building message thread lists
- handling persistence failures
- applying the persistence timeout
- providing the encouragement feature

### Sanitisation

`MessageSanitizer`

Sanitises user-supplied strings before they are stored.

Unsafe characters such as HTML angle brackets and quotes are converted to safe text representations.

### Controller

`MessagingController`

Handles HTTP requests for the Messaging component.

Main endpoints include:

- `GET /messages`
- `POST /messages/send`
- `GET /messages/conversation`
- `GET /messages/threads`

### Exception Handling

`MessagingException`

Represents errors related to messaging operations.

`MessagingExceptionHandler`

Uses Spring controller advice to catch MessagingException and return a user-friendly error page.

## Persistence

Messages are stored in an H2 database through Spring Data JPA.

The current persistent model uses one Message entity.

The sender and receiver are currently stored as String usernames rather than foreign keys to a separate User table.

This reflects the current Messaging component implementation and keeps the component independent while the other Cupid components are being developed.

## Message Threads

Message threads are generated by retrieving all messages where the selected username appears as either the sender or receiver.

Duplicate conversation partners are removed so that each user appears once in the thread list.

The most recently encountered conversations appear first because messages are retrieved in descending timestamp order.

## Conversation History

Conversation history is retrieved in both directions.

For example, a conversation between Safwan and Alex includes:

- Safwan → Alex
- Alex → Safwan

The results are ordered by sent time so that the conversation can be displayed chronologically.

## Input Sanitisation

Before a message is persisted, the following values are sanitised:

- sender
- receiver
- content

The MessageSanitizer converts potentially unsafe characters into safe HTML representations and removes unnecessary surrounding whitespace.

## Encouragement Setting

The application contains a configurable setting:

`messaging.encouragement.enabled`

When enabled, the Messaging page displays an encouragement message inviting the user to start a conversation.

When disabled, the encouragement message is not shown.

This allows the feature to be controlled by changing one configuration value.

## Persistence Timeout and Failure Handling

The persistence timeout is configured using:

`messaging.persistence.timeout.seconds`

The current value is five seconds.

Repository operations are executed with this timeout.

If persistence takes longer than the configured limit, or if a database access failure occurs, the service throws a MessagingException.

The exception handler then displays a user-friendly error page rather than exposing an internal application error.
